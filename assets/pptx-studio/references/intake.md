# 需求收集

## 先从已有信息里提取

在提问之前，先从用户消息、附件和对话历史里提取下列字段。能确定的不要再问。

| 字段 | 说明 | 缺失时 |
|---|---|---|
| topic | 主题 | 必须有；没有就请用户提供 |
| purpose | 用途：汇报、路演、教学、答辩、宣讲、培训等 | 按主题推断 |
| audience | 受众：管理层、客户、学生、评委、大众等 | 按用途推断 |
| slideCount | 页数 | 按内容量推断，通常 8–15 页；用户材料很多时可以问 |
| language | 页面语言 | 与用户消息的语言相同 |
| brand | 品牌色、logo 文件、指定字体 | 没有就不用 |
| mustInclude | 必须出现的内容、数据、图表 | 从材料里提取 |
| style | 整体风格 | **用户未明确时必须询问** |
| complexity | 复杂程度 | **用户未明确时必须询问** |
| textDensity | 文字量 | **用户未明确时必须询问** |

### 怎样算"用户已明确"

- 风格：用户说出了风格名或可以直接对应到某个风格的描述，例如"科技感""简约商务""国风""像苹果发布会"。只说"好看点""专业点"不算明确。
- 复杂程度：用户提到了"极简/简约/留白多"或"精美/丰富/华丽/满铺/装饰越多越好"之类的描述，或给了能看出装饰密度的参考图。"留白多"指装饰少、版面干净，不是允许整页空。
- 文字量：用户提到了"少字/演讲用/一页一个观点"或"详细/给别人自己看/像报告"之类的描述。
- 用户给了参考 PPT 或截图时，从参考里判断三项参数，并在大纲确认时告诉用户你的判断。

## 一次问完

三项设计参数中任何一项缺失，就在**一次** `ask_user_question` 调用里把缺失的项一起问。页数无法推断时也放进同一次调用。不要分多轮追问。

### 风格选项怎么出

从 [styles.md](styles.md) 中挑出最适合该主题和场合的 3–4 个风格。每个选项的 description 写一句画面描述，让用户不看图也能想象出来。最推荐的放第一个，标签末尾加 `(Recommended)`。用户可以用自定义回答描述自己想要的风格；这时把描述映射到最接近的风格，再按描述调整配色或装饰。

### 示例调用

```json
{
  "questions": [
    {
      "id": "style",
      "header": "整体风格",
      "question": "这份「2026 年度产品发布」PPT 想要什么整体风格？",
      "options": [
        { "label": "科技深色 (Recommended)", "description": "深蓝黑底，发光线条与数据光点，适合发布会和技术产品" },
        { "label": "商务简约", "description": "白底加一种品牌色，版式干净，内容铺满，稳重专业" },
        { "label": "清新渐变", "description": "柔和的彩色渐变与圆润图形，现代、轻快" },
        { "label": "扁平插画", "description": "扁平风格的场景插画，亲和、易懂" }
      ]
    },
    {
      "id": "complexity",
      "header": "复杂程度",
      "question": "页面装饰和配图希望有多丰富？",
      "options": [
        { "label": "均衡 (Recommended)", "description": "四周少量装饰，部分页面有配图，内容铺满版面" },
        { "label": "极简", "description": "纯色底，只有文字和数据，没有装饰；生成最快" },
        { "label": "简约", "description": "背景干净，只在边角有一两处淡装饰，靠内容与卡片铺满" },
        { "label": "复杂", "description": "有氛围的场景背景，装饰从四周延伸，大部分页面有配图" },
        { "label": "华丽", "description": "满铺多层装饰，细节繁复，文字放在饰板上，像精绘海报；生成最慢" }
      ]
    },
    {
      "id": "textDensity",
      "header": "文字量",
      "question": "每页放多少文字？",
      "options": [
        { "label": "少 (Recommended)", "description": "一页一个观点，标题加 3 条以内短句，适合现场演讲" },
        { "label": "中", "description": "标题加 4–5 条要点，每条一句话，演讲和阅读都适用" },
        { "label": "多", "description": "要点更详细，可含段落和表格，适合发给别人自己阅读" }
      ]
    }
  ]
}
```

推荐项按场合选：现场演讲推荐文字量"少"，发给别人阅读的报告推荐"多"；发布会、路演推荐复杂度"复杂"；节庆、年会、文化品牌推荐"华丽"；内部汇报推荐"简约"或"均衡"；推荐项放第一个。

## 写入 brief.json

收集完成后写入 `.pptx-studio/<deck-id>/brief.json`，格式见 [deck-format.md](deck-format.md#brief)。`decidedBy` 记录每项参数是用户选的（`user`）还是你替用户定的（`assistant`），交付时需要说明。
